CloudEval CLI

Agent-ready terminal and MCP tooling for CloudEval projects, reports, billing, recipes, chat, and one-shot asks.

curl -fsSL https://cli.cloudeval.ai/install.sh | bash

After install, run cloudeval login, cloudeval status, and cloudeval chat. Login uses cloudeval.ai device approval. Interactive terminals show CLI onboarding steps for new or incomplete accounts; headless login uses fast Playground setup. The installer can optionally detect Codex, Claude Desktop, Cursor, and VS Code, then help configure MCP for selected clients. Release downloads prefer compressed assets when available, show progress in interactive terminals, and use timeout/stall checks so slow CDN transfers fail clearly instead of appearing stuck.

First commands

cloudeval ask "Summarize my cloud risk" --format json
cloudeval agent "Find cost and architecture risks" --format json
cloudeval recipes list
cloudeval projects list
cloudeval reports list
cloudeval capabilities --format json
cloudeval help agents

Ask and Agent modes

ask is optimized for direct one-shot answers. agent uses CloudEval Agent mode for deeper non-interactive planner/tool execution.

cloudeval ask Summarize this project --project <id> --format json
cloudeval agent Find cost and WAF risks --project <id> --format json
cloudeval chat --mode agent
cloudeval setup --mode agent --non-interactive

Quotes are optional for simple multi-word prompts; use them when the shell would otherwise interpret punctuation, leading dashes, newlines, or spacing.

For text, JSON, and markdown output, ask/agent progress stays on stderr so stdout remains pipeable. Interactive terminals show one live status line with a loader, reasoning progress bar, completed/total step count, and current thinking step; captured logs fall back to append-only stderr events. Use --progress none or --quiet to suppress progress, or --format ndjson --progress ndjson to stream progress and answer events on stdout.

If CloudEval asks for human approval, interactive ask/agent prompts on stderr and then resumes the same thread. With --non-interactive, the command exits with code 6 and returns HITL_REQUIRED in JSON/NDJSON output. If CloudEval completes without final answer content, the command exits non-zero with a clear error instead of returning an empty result.

Recipes and Skills

Recipes are reusable CloudEval workflows backed only by implemented CLI and MCP capabilities. The initial recipes cover cost review, WAF triage, architecture review, template project review, report summary, billing review, diagram export, and MCP setup.

cloudeval recipes list
cloudeval recipes show cost-review
cloudeval recipes run cost-review --project <id> --format json --non-interactive

Ask/agent-backed recipes may consume model credits. Recipes that would create projects, write files, open browsers, change MCP config, or start checkout flows print explicit commands instead of doing those side effects implicitly. Public agent skill files live in the repository under skills/.

Update

Check or install the latest published CLI release without reinstalling manually:

cloudeval update --check
cloudeval update --yes

The default update output is a readable summary. In an interactive terminal, cloudeval update can also offer optional MCP onboarding for detected, all, or selected agent clients after the binary update. Use --yes for unattended updates and --format json, --format ndjson, or --format markdown for automation.

Sensitive output

The CLI redacts account IDs, session IDs, tenant IDs, and sensitive URL query parameters by default. Use --show-sensitive-ids only for trusted local workflows that require full identifiers.

cloudeval auth status
cloudeval auth status --show-sensitive-ids

Access keys for automation

Create project-scoped credentials for CI, MCP, and agent workflows. The one-time access key is returned only from the create command, and access keys cannot receive credentials:manage.

cloudeval credentials templates --format json
cloudeval credentials create --template ci --name github-actions-prod --project <id> --expires 90d --format github-actions
cloudeval identity --format json
cloudeval capabilities --live --format json

Use --access-key, --access-key-stdin, or CLOUDEVAL_ACCESS_KEY for non-interactive automation. The beta --api-key names now fail with a migration error.

MCP server for agents

Expose CloudEval to Codex, Claude Desktop, Cursor, and other MCP clients:

cloudeval mcp serve
cloudeval mcp serve --toolset readonly

Codex CLI setup:

codex mcp add cloudeval -- cloudeval mcp serve
codex mcp list

Claude Desktop, Cursor, and VS Code setup helpers:

cloudeval mcp setup claude --dry-run --toolset reports --format json
cloudeval mcp setup cursor --dry-run --toolset billing --format json
cloudeval mcp setup vscode --dry-run --toolset readonly --format json

Generic MCP clients and Ollama-powered agent hosts can use a standard stdio config:

cloudeval mcp setup generic --dry-run --toolset readonly --format json
  • Tools: capabilities_get, projects_list, projects_get, connections_list, connections_get, projects_export_diagram, ask, models_list, auth_status, status, doctor, recipes_list, recipes_get, recipes_run, reports_list, reports_run, reports_download, billing_summary, billing_usage, billing_ledger, billing_plans, billing_topups, and open_url.
  • Recipes: cloudeval://recipes plus prompts for cost-review, waf-triage, architecture-review, template-project-review, report-summary, billing-review, diagram-export, and mcp-setup.
  • Compatibility: legacy dotted tool calls still work as aliases, but MCP clients should use underscore names.
  • Auth: run cloudeval login or cloudeval login --headless before starting the MCP server, or provide CLOUDEVAL_ACCESS_KEY / --access-key from a scoped credential. Stdin is reserved for JSON-RPC messages.
  • Transport: newline-delimited stdio JSON-RPC for modern clients, with legacy Content-Length framing accepted. Protocol messages use stdout; server diagnostics use stderr.
